# ZET 139 Библиотека для коммуникации

Кроссплатформенная библиотека на языке C для получения сигналов трёхосевых датчиков ZET 139 по протоколу Modbus RTU через виртуальный COM-порт USB.

## Возможности

- **Кроссплатформенная поддержка**: Совместимость с Windows и Linux
- **Автоматический поиск датчика**: Поиск на USB по VID, PID и серийному номеру
- **Постоянная запись данных**: Три оси (X, Y, Z) пишутся в фоновом потоке в циклические буферы на 5 секунд
- **Получение последних N отсчётов**: Данные любой оси в единицах измерения канала (g)
- **Пропуски данных**: Время ведётся по часам датчика, на месте пропущенных отсчётов ставится NaN
- **Две частоты дискретизации**: Номинальная (при подключении) и фактическая (обновляется раз в секунду)
- **Автоматическое переподключение**: При потере связи датчик ищется и подключается заново

## Обзор API

### Основные функции

```c
// Подключение и отключение
zet139_connect(uint64_t serial, struct zet139_device** device_ptr);
zet139_disconnect(struct zet139_device** device_ptr);

// Состояние датчика
zet139_get_state(struct zet139_device* device, struct zet139_state* state);

// Получение данных
zet139_channel_get_data(struct zet139_device* device, uint32_t channel, float* data, uint32_t size);
```

- `zet139_connect` ищет датчик (`serial` = 0 — первый найденный), подключается и сразу начинает запись в фоне.
- `zet139_channel_get_data` копирует в `data` последние `size` отсчётов оси `channel` (0 — X, 1 — Y, 2 — Z). Значения идут от старых к новым: `data[size - 1]` — самое свежее.

### Структуры данных

```c
struct zet139_state {
    uint16_t connected;          // 1 — датчик на связи и данные пишутся
    float frequency;             // Номинальная частота дискретизации, Гц
    float frequency_real;        // Фактическая частота, Гц (0 — ещё не прочитана)
    uint64_t serial;             // Серийный номер найденного датчика
    char port[32];               // COM-порт ("COM3", "/dev/ttyACM0")
};
```

## Пример использования

```c
#include "zet139.h"
#include <stdio.h>
#include <stdlib.h>

int main() {
    struct zet139_device* device = NULL;

    // Подключение к первому найденному датчику
    if (zet139_connect(0, &device) != 0) {
        fprintf(stderr, "Ошибка подключения\n");
        return -1;
    }

    // Состояние датчика
    struct zet139_state state;
    zet139_get_state(device, &state);

    // Буфер на одну секунду отсчётов
    uint32_t size = (uint32_t)state.frequency;
    float* data = malloc(size * sizeof(float));

    // ... ждём накопления данных (пока zet139_channel_get_data возвращает -4) ...

    // Чтение последней секунды по оси Z
    if (zet139_channel_get_data(device, 2, data, size) == 0) {
        printf("Получена последняя секунда оси Z\n");
    }

    // Очистка ресурсов
    free(data);
    zet139_disconnect(&device);

    return 0;
}
```

Полный пример — `example/example_zet139.c`: раз в секунду печатает частоту датчика и среднее значение каждой оси (NaN в среднее не входят). Серийный номер нужного датчика (hex) можно передать первым аргументом.

## Обработка ошибок

Все функции возвращают 0 при успехе и отрицательные значения при ошибке.

`zet139_connect`: -1 — неверные аргументы, -2 — нехватка памяти, -3 — датчик не найден, -4 — не удалось открыть порт, -5 — датчик не ответил, -6 — не удалось создать поток.

`zet139_channel_get_data`: -1 — неверные аргументы, -2 — неверный канал, -3 — неверный размер (0 или больше буфера), -4 — недостаточно данных, -5 — связь потеряна (идёт переподключение).

## Протокол обмена

Библиотека взаимодействует с датчиком по Modbus RTU через виртуальный COM-порт USB.

### Получение данных

Данные записываются в циклические буферы (5 секунд) постоянно с момента подключения. `zet139_channel_get_data` копирует **последние** `size` отсчётов: например, при `size` = частота — последнюю секунду.

- `size` больше буфера (5 секунд) — ошибка -3;
- с момента подключения накоплено меньше `size` отсчётов — ошибка -4;
- связь с датчиком потеряна (идёт переподключение) — ошибка -5.

Чтение датчика:

- за один Modbus-запрос из FIFO датчика забирается до 125 регистров (максимум, который допускает Modbus) — для формата int16 это заголовок 16 байт и до 39 кадров по 6 байт (X, Y, Z по 2 байта);
- чтение из FIFO забирает данные: одни и те же отсчёты датчик повторно не присылает;
- пока данные есть, следующий запрос идёт сразу, без пауз; если FIFO пуст — пауза 10 мс.

### Частота дискретизации

- `frequency` — номинальная частота: читается из регистров канала при каждом подключении. По ней выбирается размер буфера (5 секунд × частота) и считаются номера отсчётов.
- `frequency_real` — фактическая частота: фоновый поток раз в секунду читает её из отдельного регистра датчика (0xC504, число float). Пока значение ни разу не прочитано — примерно секунду после первого подключения — в поле лежит 0. После переподключения остаётся последнее прочитанное значение, а если параметры датчика изменились — снова 0.

Обе частоты — `float`. Чтобы получить размер блока «одна секунда», приводите номинальную частоту к целому: `(uint32_t)state.frequency`.

### Пропуски данных (NaN)

Время ведётся по часам самого датчика — системное время компьютера не используется:

- в заголовке каждой порции датчик сообщает `seconds` (целые секунды его работы) и `counter` (номер отсчёта внутри секунды); вместе это номер первого отсчёта порции: `seconds × frequency + counter` (берётся целая часть номинальной частоты);
- перед записью порции её начало сравнивается с концом предыдущей (начало + число кадров):
  - совпало — данные непрерывны, порция просто дописывается;
  - позже — часть отсчётов пропущена: на их место пишется NaN (если пропуск длиннее буфера — весь буфер становится NaN);
  - раньше — время ушло назад (например, датчик перезапустился): весь буфер очищается (NaN) и запись идёт с начала.

NaN считаются хранимыми отсчётами: `zet139_channel_get_data` может вернуть блок, часть которого — NaN. Среднее и другие расчёты по такому блоку нужно вести, пропуская NaN (`x == x` — false только для NaN).

### Потеря связи

- связь считается потерянной при первой же ошибке обмена (или некорректном ответе) либо если 10 секунд нет корректного ответа;
- порт закрывается, `state.connected` становится 0, `zet139_channel_get_data` возвращает -5;
- раз в секунду датчик с тем же серийным номером ищется на USB, порт открывается, параметры читаются заново, запись продолжается;
- если параметры датчика (формат данных, номинальная частота, вес разряда) не изменились, буферы с накопленными данными сохраняются, а время без связи заполняется NaN по часам датчика (если датчик за это время перезапустился и его время пошло назад — буферы очищаются); фактическая частота `frequency_real` в сравнении не участвует;
- если параметры изменились, буферы создаются заново (заполнены NaN), накопление начинается с нуля: пока не набралось `size` отсчётов, `zet139_channel_get_data` возвращает -4.

## Поддержка платформ

### Windows

- Файлы проектов Visual Studio можно сгенерировать с помощью CMake
- Рекомендуется использовать [vcpkg](https://vcpkg.io/en/getting-started.html)
- Поиск датчика: в реестре `HKLM\SYSTEM\CurrentControlSet\Enum` ищутся устройства `VID_2FFD&PID_xxxx` с PID ZET 139; имя подраздела — серийный номер, COM-порт берётся из `Device Parameters\PortName`. Порт должен присутствовать в `HKLM\HARDWARE\DEVICEMAP\SERIALCOMM` (устройство подключено сейчас)

### Linux

- Поиск датчика: перебираются `/sys/class/tty/ttyACM*`, у USB-устройства проверяются `idVendor`, `idProduct`, `serial`
